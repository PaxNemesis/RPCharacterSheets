# RPCharacterSheets

Multi-system tabletop RPG character sheets. React 19 + TypeScript single-page app, built with Vite and pnpm, deployed to GitHub Pages.

## Commands

- `pnpm install` — install dependencies (pnpm comes from Corepack; run `corepack enable pnpm` if it's missing)
- `pnpm dev` — dev server at http://localhost:5173
- `pnpm build` — production build, then type check
- `pnpm lint` — lint with oxlint
- `pnpm test` — run the unit tests once with Vitest (`pnpm test:watch` to rerun on changes)

Before finishing a change, run `pnpm build`, `pnpm lint` and `pnpm test` and make sure all three pass. The deploy workflow runs the tests before building.

## Tests

- Vitest with jsdom and Testing Library, configured in the `test` block of `vite.config.ts`. `src/test/setup.ts` adds the jest-dom matchers and clears the DOM and localStorage after each test.
- Tests go in a `__tests__/` folder inside the component or page folder they cover (`src/pages/IronKingdomsFmf/__tests__/migrate.test.ts`), and may import that folder's internals with relative paths.
- Add tests for rules, formulas and migrations whenever you change them.

## Code conventions

Before creating or editing any `.ts` or `.tsx` file, read and follow [.github/instructions/frontend.instructions.md](.github/instructions/frontend.instructions.md). It covers component folder layout, naming, exports, styles, `index.ts` entry points, encapsulation and imports.

## Project layout

- `src/routes/` — TanStack Router file-based routes. Each file only defines a route and points at a page component; no components live here. Route files must export `Route`.
- `src/pages/` — one component folder per page (`Home`, `About`, `NotFound`, and one per game system such as `IronKingdomsFmf`).
- `src/components/` — shared components, including `RootLayout` (nav and `<Outlet />`), `CharacterWorkspace` (character tabs, browser autosave, JSON save/load) and the sheet field components.
- Game rules (stats, formulas, constants) live in that system's page folder, never in shared components. The site is public: copy only names, numbers and page references from rulebooks, not rules text.
- `src/index.css` — global styles, theme variables and the `--space-*` spacing tokens (see Spacing in the frontend instructions). Component styles go in each component's `<Component>.styles.css`.
- Import across folders with the `@/` alias (`@/pages/Home`), which points at `src/`.

## Things to know

- `src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin whenever routes change. Never edit it by hand. It is committed so types work before the first build.
- `pnpm build` runs `vite build` before `tsc -b`, because the Vite build generates the route tree that type checking needs. Keep that order.
- The site is served from `/<repo-name>/` on GitHub Pages. Never hardcode root-relative URLs like `/icons.svg`: use imports, `import.meta.env.BASE_URL`, or router `<Link>`s.
- Deployment is `.github/workflows/deploy.yml`. It runs on every push to `main`, sets `BASE_PATH` from the repo name, and copies `index.html` to `404.html` so deep links work.

## Character data

Each game system is a `SheetSystem` (in `<System>/utils/<system>.ts`). Characters are saved to the browser and to JSON files. Loading a JSON file or the browser's copy goes through the system's `migrate`, then `mergeDefaults`, which fills in missing fields and replaces values of the wrong type with the default.

- When you change the shape of saved data (renaming, moving or retyping a field), bump the system's `version` and add a step to its `utils/migrate.ts`. Write steps so they are safe to run twice. A new field with a default needs no migration.
- When you add a list to the character, add a blank entry for it to the system's `utils/listItems.ts`, keyed by its path without indexes (`classes.skills`). Without one, entries in that list are loaded unchecked.
- Optional fields that aren't in `createCharacter` (such as an item's `forms`) aren't type-checked on load. Code reading them should cope with a wrong value, or the field should get a default.
- Treat every loaded value as untrusted: a file can be edited by hand. Render data as text through React, never with `dangerouslySetInnerHTML`, and never put it in `href`, `src` or `style`. Images are shown only through `ImageField`, which accepts raster `data:image/` URLs and hides anything else.
- `CharacterWorkspace` wraps each sheet in an error boundary, so a character that still fails to render shows a recovery message instead of breaking the page. That is a safety net, not a substitute for the checks above.
