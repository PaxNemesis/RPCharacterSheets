# RPCharacterSheets

Multi-system tabletop RPG character sheets. React 19 + TypeScript single-page app, built with Vite and pnpm, deployed to GitHub Pages.

## Commands

- `pnpm install` — install dependencies (pnpm comes from Corepack; run `corepack enable pnpm` if it's missing)
- `pnpm dev` — dev server at http://localhost:5173
- `pnpm build` — production build, then type check
- `pnpm lint` — lint with oxlint

Before finishing a change, run `pnpm build` and `pnpm lint` and make sure both pass. There is no test suite yet.

## Code conventions

Before creating or editing any `.ts` or `.tsx` file, read and follow [.github/instructions/frontend.instructions.md](.github/instructions/frontend.instructions.md). It covers component folder layout, naming, exports, styles, `index.ts` entry points, encapsulation and imports.

## Project layout

- `src/routes/` — TanStack Router file-based routes. Each file only defines a route and points at a page component; no components live here. Route files must export `Route`.
- `src/pages/` — one component folder per page (`Home`, `About`, `NotFound`, and one per game system such as `IronKingdomsFmf`).
- `src/components/` — shared components, including `RootLayout` (nav and `<Outlet />`), `CharacterWorkspace` (character tabs, browser autosave, JSON save/load) and the sheet field components.
- Game rules (stats, formulas, constants) live in that system's page folder, never in shared components. The site is public: copy only names, numbers and page references from rulebooks, not rules text.
- `src/index.css` — global styles and theme variables. Component styles go in each component's `<Component>.styles.css`.
- Import across folders with the `@/` alias (`@/pages/Home`), which points at `src/`.

## Things to know

- `src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin whenever routes change. Never edit it by hand. It is committed so types work before the first build.
- `pnpm build` runs `vite build` before `tsc -b`, because the Vite build generates the route tree that type checking needs. Keep that order.
- The site is served from `/<repo-name>/` on GitHub Pages. Never hardcode root-relative URLs like `/icons.svg`: use imports, `import.meta.env.BASE_URL`, or router `<Link>`s.
- Deployment is `.github/workflows/deploy.yml`. It runs on every push to `main`, sets `BASE_PATH` from the repo name, and copies `index.html` to `404.html` so deep links work.
